### Authentication follow-up — 2026-10-08

- Local accounts reject Google login with a password-login warning. Google accounts reject password login and password registration with a Google-login warning. Email lookups are normalized; any stored Google provider ID must match, and the frontend callback requires Google's verified-email claim before exchange.
- 2FA remains optional for admins/coadmins only. Customers cannot set up, confirm, disable or exchange a factor; legacy customer settings do not trigger login challenges. Conditional enrollment writes prevent overwriting enabled factors or confirming a stale pending setup.
- Staff authorization requires the current database role to be admin, or coadmin with the requested permission, including access to another customer's order. Customer rows with leftover permissions are denied. UI permission checks mirror this policy.
- Google sign-in displays loading, bypasses the authentication form's unsaved-input warning, requests the account chooser, preserves the return path/query and restores the form on a redirect-request failure/timeout. OAuth handoffs are consumed once; factor challenges do not reopen after dismissal. Protected pages wait for the handoff before prompting.
- Verified locally: 233 backend tests, 58 frontend tests, backend build, frontend production build and lint on changed frontend files. HTTP tests cover all 68 private routes for missing/challenge tokens, all 48 staff routes for demoted customers with stale permissions, the internal OAuth boundary and factor-management throttling. Model writes and hook lifecycle are mocked; real database concurrency and live Google/browser flows still need smoke checks.
- Deployment: release frontend and backend together, run translation sync for the loading/provider-warning translations, then test both provider mismatches, customer login, admin/coadmin 2FA, cancellation/Back, and return to checkout after Google login. No deployment or production database changes were made in this pass.
